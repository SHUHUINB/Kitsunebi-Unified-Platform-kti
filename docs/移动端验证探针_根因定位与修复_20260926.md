> 日期：2026-09-26
> 服务器：`203.0.113.10`
> 症状：手机（Kitsunebi，SOCKS5 `8889`，账号 `TestPass1!`）访问 `http://m.baidu.com`
> 页面**不显示**「验证成功」，看到的是真实百度页面。
> 约束：用户明确**不安装** Charles CA 证书。

## 二、根因链（全部实测）

### 2.1 设备实际走的是 HTTPS:443，不是 HTTP:80

适配层日志（账号 `TestPass1!` = 你的手机）：

```
2026-09-26 01:28:00,880 INFO SOCKS5 m.baidu.com:80  -> charles   (存活 59ms)
2026-09-26 01:28:00,978 INFO SOCKS5 m.baidu.com:80  -> charles   (存活 75ms)
2026-09-26 01:28:23,759 INFO SOCKS5 m.baidu.com:443 -> charles
2026-09-26 01:28:23,777 INFO SOCKS5 fclick.baidu.com:443 -> charles
```

全量统计：`m.baidu.com:443` **39 条**，`m.baidu.com:80` **12 条**，
且 `:80` 那几条大多只存活 60~75ms —— 是浏览器的连通性探测，真正的页面请求全走 `:443`。

**结论**：现代浏览器对 `m.baidu.com` 强制 HTTPS，`:80` 那条映射根本轮不到。

### 2.2 `:443` 那条映射从未启用

`/home/ubuntu/.charles.config` 第 277-292 行：

```xml
<mapMapping>                      <!-- :80 -->
  <sourceLocation><protocol>http</protocol><host>m.baidu.com</host><port>80</port></sourceLocation>
  <destLocation>...<port>8890</port><path>/socks</path><query>via=map</query></destLocation>
  <enabled>true</enabled>
</mapMapping>
<mapMapping>                      <!-- :443 -->
  <sourceLocation><protocol>https</protocol><host>m.baidu.com</host><port>443</port></sourceLocation>
  <destLocation>...<port>8890</port><path>/socks</path><query>via=map</query></destLocation>
  <enabled>false</enabled>        <!-- ← 从来就是 false，不是被谁关掉的 -->
</mapMapping>
```

### 2.3 就算启用 `:443`，也绕不开证书

Charles 当前 `decryptSSL=true` + `sslLocations=[*:443]`，对所有 HTTPS 做 MITM。
用**不信任** Charles CA 的客户端实测：

```
$ curl -x http://127.0.0.1:18888 https://m.baidu.com/
* SSL certificate problem: self-signed certificate in certificate chain
```

**这正是你之前遇到「无法连接」的根因。** 只要不装证书，任何 HTTPS 改写都无解。

### 2.4 ★ 真缺口：适配层的上游选错了 Charles 的面

Charles 两个面行为**不一样**（实测）：

| 测试 | 结果 |
|---|---|
| Charles **HTTP 代理口**(18888) + CONNECT `m.baidu.com:80` | ✅ 命中 Map Remote |
| Charles **HTTP 代理口**(18888) + CONNECT `m.baidu.com:8080` | ❌ **不解析，纯隧道** |
| Charles **SOCKS5 口**(18889) + `m.baidu.com:80` | ✅ 命中 |
| Charles **SOCKS5 口**(18889) + `m.baidu.com:8080` | ✅ **命中** |

原因：Charles 的 SOCKS 口开了 `enableSOCKSTransparentHTTPProxying=true`，
**对所有端口**的明文 HTTP 都做解析；而 HTTP 代理口只对 CONNECT 到 **80** 的隧道解析。

适配层原来固定走 HTTP 代理口（`charles_http_port=18888`）发 CONNECT —— 这就是缺口。

## 三、改动内容

### 3.1 适配层 `ccproxy_adapter.py`

- 新增 `connect_upstream_socks()`：以 SOCKS5 协议连 Charles 的 `charles_socks_port`，
  目标用**域名**形式交给 Charles 远端解析（保证抓包与映射匹配看到的是域名）。
- `connect_upstream()` 改为按 `charles_upstream` 分派，默认 `socks5`，保留 `http` 旧路径。
- `DEFAULT_CONFIG` 新增 `charles_socks_port: 18889`、`charles_upstream: "socks5"`。
- 启动日志改为打印实际出口链：

```
出口链到花瓶  127.0.0.1 (upstream=socks5, http=18888, socks=18889)
```

### 3.2 Charles `~/.charles.config`

**仅追加**一条映射，不动任何现有条目、不动 `decryptSSL`、不动 `sslLocations`：

```xml
<mapMapping>
  <sourceLocation><protocol>http</protocol><host>m.baidu.com</host><port>8080</port></sourceLocation>
  <destLocation><protocol>http</protocol><host>127.0.0.1</host><port>8890</port>
                <path>/socks</path><query>via=map</query></destLocation>
  <preserveHostHeader>false</preserveHostHeader>
  <enabled>true</enabled>
</mapMapping>
```

**为什么用 `:8080`**：浏览器只对**默认端口 80** 做 HTTPS 升级；
非标端口的 http 绝对保持明文，一定走代理、一定命中。

## 六、待你决定：HTTPS 解密的取舍

现在 `decryptSSL=true` + `sslLocations=[*:443]` 意味着 **Charles 拦截所有 HTTPS**。
手机不装 CA 时，**所有 HTTPS 网站都会证书报错**（不只是 m.baidu.com）。

两条路只能选一条：

| 方案 | 效果 | 代价 |
|---|---|---|
| **A. 关掉 HTTPS 解密** | 手机免装证书，所有 HTTPS 网站正常访问；`http://m.baidu.com:8080/` 验证照常可用 | 无法再抓 HTTPS 明文包 |
| **B. 保持解密** | 能抓 HTTPS 包；`https://m.baidu.com` 也能被改写 | 手机**必须**安装 Charles CA（`http://203.0.113.10:8890/ca.crt`） |

**未执行** —— 这一项影响抓包能力，等你确认后再动。
